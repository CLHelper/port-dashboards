The ladder

  1. 0% · GroundworkTools, formats and loaders; the game's own executable has not been run yet.
  2. 15% · Executable runsThe game's code starts: its entry point runs and its imports are answered.
  3. 25% · Graphics deviceIt creates its graphics device, queues and command lists, but nothing reaches the screen.
  4. 35% · First frameFrames reach the screen, even blank or garbled ones.
  5. 50% · MenusThe game's own screens are drawn: first-boot screens, menus or the intro video.
  6. 62% · World loadsIt loads into the game world, though the picture may still be dark or incomplete.
  7. 78% · In-gamePlayer control in the world, with a recognisable picture.
  8. 100% · PlayableIn-game for 30 minutes or more without a crash, at 20 frames a second or better.

The approaches

  • Compatibility layerRuns the console executable's x86-64 code directly on the PC and supplies the console's system libraries and graphics API underneath it, translating the GPU programs on the way.
  • RecompilerTranslates the console executable, or the parts of it that differ, into a new PC program ahead of time.
  • EmulatorEmulates the console's hardware or operating system broadly, not only the interfaces this game calls.
  • Boot harnessA focused harness that boots this one game to test parts of the pipeline, with stand-ins where the rest is missing.
  • ForkBuilds on another tracked project, adding its own fixes or changes the original has not merged.
  • Other routeA different way to the PC, for example through another console's build.
